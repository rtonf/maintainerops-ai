# v0.1.15 Quality Hardening Security Diff Review: 2026-07-11

This API-free security diff review covers the quality and evidence hardening prepared after the repository-wide product review. The review is scoped to the branch diff from `main`; it is not a replacement for the next release-candidate repository-wide Codex Security scan.

## Scope

- Offline risk and test-file signal changes
- CLI and fixture input validation
- Deterministic and model-backed eval gates
- GitHub Action Step Summary and multiline output handling
- npm Trusted Publishing tag/version guard
- Node.js compatibility CI, CodeQL permission placement, and Scorecard SARIF upload
- Generated `dist-action/index.js` runtime
- Related public documentation and maintenance evidence

## Security Boundary Review

- Action reports remain redacted and GitHub workflow-command syntax is neutralized before they reach stdout, the Step Summary, or `GITHUB_OUTPUT`.
- The multiline output delimiter is generated per run and regenerated on collision, preventing packet text from terminating the output record.
- The README warns consumers not to execute model or heuristic packet text as shell code.
- Action fixture paths now resolve from the caller workspace, but fixture execution remains explicit and does not add repository write permissions.
- CLI numbers and nested fixture fields fail closed before GitHub or OpenAI analysis starts.
- Empty eval sets cannot produce false passing evidence.
- Model-backed evals reject unknown pricing and perform a conservative request-cost preflight before every API call, followed by actual usage accounting.
- npm publication now rejects prerelease events and any release tag that does not exactly match the stable `package.json` version.
- Scorecard's `security-events: write` permission is limited to the scheduled/manual Scorecard job. CodeQL's matching permission is moved from workflow scope to its analysis job.
- Pull request CI retains read-only repository permissions and does not receive OpenAI or npm publishing secrets.
- Test discovery enumerates only compiled `.test.js` and repository-owned `.test.mjs` files before passing explicit paths to the Node.js test runner.
- No merge, close, label, comment, release, or repository mutation behavior was added.

## Result

No reportable security findings were identified in the reviewed diff.

## Residual Risk

- Step Summary content is maintainer-visible untrusted text and relies on GitHub's Markdown sanitization in addition to MaintainerOps redaction. It must remain advisory.
- The conservative API preflight depends on the explicit pricing table and output-token ceiling; new models must not be enabled until pricing is reviewed.
- Scorecard alert closure depends on the first successful post-merge SARIF upload.
- External maintainer feedback remains absent and cannot be replaced by owner-generated evidence.
