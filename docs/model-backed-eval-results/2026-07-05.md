## Findings From Failed Attempts

The first run exposed useful product and eval-harness gaps:

- Several low-risk issue cases used reasonable actions such as `needs_human_review` instead of the single expected `needs_more_info`.
- Dependency update PRs needed project-policy label completion for `security-review` and `release-notes`.
- License metadata issues needed risk capping so repository metadata cleanup is not treated like a vulnerability.
- A clear token permission bypass PR should normalize recommended action to `needs_security_review`, not only add a `security-review` label.

## Follow-Up Implementation

- Added acceptable recommended actions for semantically equivalent maintainer workflows.
- Added dependency-update post-processing for `security-review` and `release-notes`.
- Added metadata-maintenance risk capping for license detection issues.
- Added direct security-boundary action normalization for bypass/missing authorization cases.
- Added unit coverage for these normalization paths.
